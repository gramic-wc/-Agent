# 4 周排期与验收标准

> 原则：每周三做 checkpoint，不达标就走降级方案（见文末），不要硬耗。
>
> **日程已按真实进度重排（2026-11-20）**：
> Day 1 实际完成了原 Day 1~3 的入库工作（含发现并修复坏字体问题）。
> 因此原 Day 2（采手册）降为可选（并入”补手册“），原 Day 3（入库）取消，
> 日程整体前移两天。每天详细任务见 `计划/Day2任务.md` 这类独立任务卡。

## W1 知识底座：从 PDF 到可检索

| 任务 | 产出 | 验收 |
| --- | --- | --- |
| 采集 15~25 份手册（含表格、含图） | `data/manuals/` | 表格类 ≥5 份、含图 ≥3 份 |
| 解析入库（`eq-ingest --no-vlm`） | `data/index/chunks.jsonl` | 三类 block_type 都有，页码/章节正确 |
| 造历史工单 + 备件 | `data/cases/cases.jsonl`、`data/parts/parts.json` | 200 条工单、≥20 条备件 |
| 图纸理解（`eq-ingest`） | figure chunk 带 `vlm_desc` | 抽 5 张图人工看描述是否准确 |

**验收线**：30 条自测 query 里，目标 chunk 进 top5 的比例 ≥ 0.8（其中 10 条必须靠型号/故障码字面命中）。

## W2 混合检索 + 引用可追溯

| 任务 | 产出 | 验收 |
| --- | --- | --- |
| 向量 + BM25 + 型号过滤 + RRF + rerank | `retrieve/hybrid.py` | 型号过滤生效（GA55 不会召回 VMC850） |
| 引用字段贯通到界面 | `Citation` 全链路 | 抽 20 条结论，引用与原文字面一致 ≥ 90% |
| 未知问题拒答 | `self_check` 分支 | 8 条域外问题（见 `dev.jsonl` r01~r08）转人工 |

## W3 Agent 作业环（核心周）

| 任务 | 产出 | 验收 |
| --- | --- | --- |
| 状态机 6 节点 + 条件边 | `agent/graph.py` | 10 个故障场景端到端跑通 |
| 作业卡 schema | `schema.WorkCard` | 字段完整率 100%（步骤≥3、工具有值、工时>0） |
| 高风险动作标红 | `Step.risk` | 带电/带压/高处/旋转件全为 high |
| 转人工 | `escalate_to_human` | 型号不明、置信度<0.35、引用缺失三条路径都能触发 |

## W4 评测 + 界面 + 交付

| 任务 | 产出 | 验收 |
| --- | --- | --- |
| 评测集校对（30 条） | `data/eval/dev.jsonl` | 每条期望原因人工确认过 |
| 跑评测 | `uv run eq-eval` | 指标填进 `docs/metrics.md` |
| Streamlit 演示 | `app/streamlit_app.py` | 左引用 / 右作业卡，5 分钟能讲完 |
| 交付物 | README + 3 分钟录屏 + 踩坑记录 | 换台机器 30 分钟内能跑起来 |

**目标数字**：cause_hit@3 ≥ 0.7、cite_coverage ≥ 0.9、reject_acc ≥ 0.8、latency_p95 < 20s。

## 降级顺序（时间不够时从上往下砍）

1. 砍备件查询（`get_spare_parts` 返回固定表）
2. 砍 PDF 高亮预览 → 只显示原文片段
3. 砍图纸理解 → 只留正文 + 表格（多模态降级为"多版式"）
4. **绝不砍**：引用可追溯、作业卡结构化、评测数字

## 每日时间预算（学习节奏，非死线）

- 工作日 2h：一天只推一个模块，睡前跑一次 `eq-eval` 看有没有回退
- 周末 6h：做集成与界面；周三 checkpoint 不到 60% 就立刻降级
