### 任务 2（20 分钟）· 测口语化 query —— 这是今天最可能翻车的地方

**为什么单独测这个**：任务 1 的 query 都是**从手册里摘的词**（"油冷却器 清洗"），
关键词能对上。但真实用户不会这么说话，用户会说：

> "3号车间GA55空压机运行20分钟后排气温度高报警并跳机，环境温度35℃"

这句话里**没有"油冷却器"三个字**，纯靠 BM25 一定搜不到，只能靠向量。
**这才是 RAG 的真实使用场景**，任务 1 测的是"检索有没有坏"，任务 2 测的是"检索够不够好"。

```powershell
uv run python -c "import json,textwrap; from eqagent.agent.tools import search_manual; rows=[json.loads(l) for l in open('data/eval/dev.jsonl',encoding='utf-8')][:8]; [print('\n###',r['id'],r['symptom'],'\n  ->',[(h['doc_title'][:16],h['device_model'],h['page'],h['score']) for h in search_manual(r['symptom'],device_model=r['device_model'] or None,top_k=5)]) for r in rows]"
```

**成功标志**：8 条里 **≥ 5 条** top5 能命中目标设备的相关内容。

**如果明显比任务 1 差**（正常会出现），这就是今天的**重要发现**，一定要记下来。
说明"口语化 query → 手册术语"之间有一道沟，这道沟后面有两个解法（W2 做）：
1. **query 改写**：让模型先把"排气温度高跳机"改写成手册里可能出现的词
2. **加 rerank 权重**：现在 rerank 已经在跑，但 top_k 只有 30，可能候选里根本没有对的

### 任务 3（15 分钟）· 量化"跨设备污染"

**昨天的观察**：搜"伺服过载 排查"时，第 2 名是 `GA55_user_manual`。
**这说明不加型号过滤时，三台设备的内容会互相污染。**

```powershell
uv run python -c "from eqagent.agent.tools import search_manual; qs=['排气温度高','主轴异响','轴承温度高','伺服报警','刀库卡刀','振动超标']; [print(q,'不过滤->',[h['device_model'] for h in search_manual(q,top_k=5)], ' 过滤GA55->',[h['device_model'] for h in search_manual(q,device_model='GA55',top_k=5)]) for q in qs]"
```

**成功标志**：能说清两件事
1. 不加过滤时，跨设备污染有多严重（几成）
2. 加了 `device_model` 过滤后，是不是真的干净了

> 这一步是 **Day 9（型号过滤）的预习**，今天不用修，只要记录。

### 任务 4（20 分钟）· 找出"没被检索到"的卡片 —— 反向检查

**为什么做这个**：前面三个任务都是"问一个问题看能不能搜到"。
反过来还要看："我入库的 2022 张卡片里，有多少是**永远搜不到**的死卡片？"

一份文档如果切出了 300 块，但每块只有 20 个字（比如表格碎行、页眉页脚），
那这些块占着向量库的位置，却永远不可能成为好的答案。

```powershell
uv run python -c "import json,collections; rows=[json.loads(l) for l in open('data/index/chunks.jsonl',encoding='utf-8')]; ts=[r for r in rows if r['block_type']=='text']; print('正文块',len(ts)); print('长度分位', [ (p, sorted(len(r['text']) for r in ts)[int(len(ts)*p/100)-1]) for p in (10,25,50,75,90,99)]); print('超短块(<40字)',sum(1 for r in ts if len(r['text'])<40)); print('超长块(>900字)',sum(1 for r in ts if len(r['text'])>900))"
```

**成功标志**：能说出"我的正文块长度中位数是 X 字，超短块有 Y 个（占 Z%）"。

**如果超短块占比 > 15%**，记下来——Day 5 或 Day 13 要处理（合并短块或过滤掉）。

## 5. 报错急救（今天可能遇到的）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `RuntimeError: 缺少索引文件` | `data/index/chunks.jsonl` 没了 | 重跑 `uv run eq-ingest --no-vlm` |
| 检索全部返回 `[]` | 索引文件在但 Qdrant 空 | 同上（`--no-vlm` 也会建向量） |
| `等 30s 没反应` | embedding 在联网 | 正常，一次 query 约 1~3 秒 |
| 中文输出乱码（终端里 `鑰冭瘯`） | PowerShell 编码 | 加 `2>$null`，或看 `docs` 里的 md 文件而不是终端 |
| `uv run python -c "..."` 报 `SyntaxError` | PowerShell 把双引号吃了 | 改用**单引号**包外部：`uv run python -c '...'`；或写成临时 `.py` 文件跑 |
| `AttributeError: 'Hit' object has no attribute 'chunk'` | 用错了字段名 | `Hit` 的字段是 `.text` / `.payload` / `.page`，**没有** `.chunk` |
| Qdrant 报 `portalocker` 错误 | 有两个进程同时开着本地库 | 关掉其他 Python 窗口再跑 |
