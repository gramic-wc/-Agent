> 用途：**你随时想知道"这个文件是干嘛的"就翻这里。**
> 按"数据怎么流动"的顺序排列，不是按字母顺序。
>
> - 想先看懂"这个项目在干嘛" → 看第 0 节的数据流图

> - 想知道"哪些文件不能碰 / 哪些是自动生成的" → 看第 8 节

data/manuals/     eq-ingest          data/index/        eq-ask

## 1. 根目录（项目大门口）

| 文件/文件夹 | 干什么的 | 你要不要动 |
| --- | --- | --- |
| `README.md` | 项目门面：一句话介绍 + 6 个命令 | 最后一天（Day 26+）会改 |
| `pyproject.toml` | **项目的说明书**：依赖哪些包、`eq-ingest` 这三个命令指向哪段代码 | 别动（加依赖才动） |
| `uv.lock` | 依赖的**精确版本锁**。保证你和别人装出来的包一模一样 | **绝对别动**（`uv` 自动写） |
| `.env` | **你的密钥文件**：API Key、模型名、各种路径 | 要动（填 Key） |
| `.env.example` | `.env` 的模板，给人看"该填哪些" | 别动 |
| `.gitignore` | 告诉 git **哪些文件不要提交**（PDF、向量库、.env） | 偶尔加一行 |
| `docker-compose.yml` | 可选：想用 Docker 跑 Qdrant 服务端时用 | 用不到（走本地模式） |
| `学习计划.md` | 4 周学习计划总纲 | 已移到 `计划/` 目录 |

### 两个真的不能碰的文件

- **`uv.lock`**：`uv sync` 会读它。手改会导致版本冲突。
- **`.env`**：里面是密钥。**已经被 git 忽略**，永远不要提交，也不要截图发出去。

## 2. `src/eqagent/` —— 项目的全部代码（核心）

这个目录名 `eqagent` = **eq**uipment（设备）+ **agent**（智能体）。
`src/` 是现代 Python 项目的统一约定：源码放 src，测试和脚本放外面。

### 2.1 最底层：配置与数据结构

| 文件 | 干什么的 | 通俗解释 |
| --- | --- | --- |
| `config.py` | 读 `.env`，定义三台设备、所有路径、模型名 | **"总开关"**：所有可调参数集中在这，别散落在各处 |
| `schema.py` | 定义数据结构：`Chunk`（卡片）、`WorkCard`（作业卡）、`Citation`（引用） | **"表格模板"**：规定了每张卡片/每张作业卡必须有哪些字段 |
| `llm.py` | 通义千问客户端：对话 / 看图 / 转向量 / 重排，四个能力统一在这 | **"电话总机"**：所有跟大模型说话都走这，方便加缓存和重试 |
| `knowledge.py` | 领域知识：12 类高频故障场景 + 备件的样子 | **"常识词典"**：造假数据、设计评测集时用它保证数据自洽 |

> **为什么 `llm.py` 要单独一个文件？**
> 因为整个项目所有模型调用都从这一个口子出去。哪天要换模型、加缓存、加日志、
> 改超时时间，只改这一个文件。这就叫"收口"。

### 2.2 `ingest/` —— 入库链路（把 PDF 变成卡片）

这是**第 1 周的全部工作**。顺序就是数据流顺序：

```
parse.py  →  chunker.py  →  quality.py  →  （image_desc.py）  →  pipeline.py 串起来
解析PDF      切块+规整       质检乱码        看图说话(VLM)          命令行入口
```

| 文件 | 干什么的 | 今天（Day 1）碰过没 |
| --- | --- | --- |
| `parse.py` | **解析 PDF**：找表格、抠图片、抽文字行、认章节标题、记页码 | 🟡 你改了它（加页级缓存） |
| `chunker.py` | **切块**：文本按句子切、表格转 Markdown 表 | ✏️ 今天动过 |
| `quality.py` | **质检**：判断一块文字是不是真字（今天新增） | ✅ 今天新建的 |
| `image_desc.py` | **图纸理解**：把插图交给 qwen-vl 生成文字描述（Day 4 才用） | ❌ 还没跑过 |
| `pipeline.py` | **总装 + 命令行入口**：`eq-ingest` 命令就是跑它 | ✅ 今天改过（加质检、跳过 `_` 目录） |
| `__init__.py` | 说明这个包干嘛的 | ❌ |

**重点理解 `pipeline.py` 干的事**（就 5 步）：

```
1. 扫描 data/manuals/ 下所有 PDF        ← 跳过 _probe 这类临时目录
2. 对每份 PDF 调 parse.py 解析 + 切块
3. 调 quality.py 逐块质检，丢掉乱码
4. 把干净的块写成 data/index/chunks.jsonl
5. 把每个块送去算 embedding，写进 data/qdrant/
```

### 2.3 `retrieve/` —— 检索层（怎么从 2022 张卡片里找到那 5 张）

| 文件 | 干什么的 | 通俗解释 |
| --- | --- | --- |
| `index.py` | Qdrant 向量库的封装：建集合、写点、滤波、查询 | **"图书馆书库管理"**：负责存放和按坐标找书 |
| `hybrid.py` | 混合检索：向量（dense）+ 关键词（BM25）→ RRF 融合 → 重排 | **"两个图书管理员"**：一个按意思找，一个按字面找，最后商量出结果 |

`hybrid.py` 是**第 2 周的主角**。它内部有两条路：

```
用户问题
  ├─→ dense：转向量（1024 个数字）→ 在 Qdrant 里找最近的 30 张卡   ← 靠"意思像"
  └─→ BM25：分词 → 按关键词匹配找 30 张卡                        ← 靠"字一样"
        ↓
     RRF 融合（把两个排名合并成一个）
        ↓
     rerank 重排（用一个更贵更准的模型重新打分，取前 6 条）
```

> **为什么必须两条路？**
> `GA55`、`E-201`、`P-1001` 这种型号/故障码/备件号**没有"语义"**，纯向量搜不准；
> 而"排气温度高怎么办"和原文写的"出口温度异常"**字面不同**，纯 BM25 又搜不到。
> 所以两条都要。

### 2.4 `agent/` —— 检修作业 Agent（第 3 周的主角）

| 文件 | 干什么的 | 通俗解释 |
| --- | --- | --- |
| `graph.py` | **状态机**：6 个节点 + 条件边，串起整个检修流程 | **"流水线工人"**：按固定工序一步步走 |
| `tools.py` | Agent 能用的工具：查手册、查历史工单、查备件、建工单 | **"工具箱"**：每个工具只干一件业务动作 |
| `run.py` | 命令行入口：`eq-ask "GA55排气温度高"` | **"门把手"** |

`graph.py` 的流程（记住这 6 步就能讲清整个项目）：

```
identify（认设备）→ retrieve（检索手册）→ diagnose（判原因）
       → plan（出作业卡）→ self_check（自检）→ finalize（交付）
                              ↓ 不通过
                         escalate_to_human（转人工）
```

**最关键的设计（面试/答辩可讲）**：

> 模型只被允许引用 `[E1]..[En]` 这种**证据编号**。
> "E3 对应哪份文档第几页"是**代码**从检索结果里查出来的，模型根本接触不到。
> 所以作业卡里**不可能出现模型编造的出处**。

### 2.5 `eval/` —— 离线评测（第 4 周）

| 文件 | 干什么的 | 通俗解释 |
| --- | --- | --- |
| `runner.py` | `eq-eval` 命令：跑 30 条测试题，算 5 个指标 | **"期中考"**：把"能演示"变成"能报数字" |

5 个指标（背下来，这是项目的量化说服力）：

| 指标 | 含义 | 目标 |
| --- | --- | --- |
| `cause_hit@3` | 前 3 条可能原因里有没有正确那个 | ≥ 0.7 |
| `cite_coverage` | 结论带可追溯引用的比例 | ≥ 0.9 |
| `card_complete` | 作业卡字段完整率 | = 1.0 |
| `reject_acc` | 知识库外问题是否正确拒答 | ≥ 0.8 |
| `latency_p95` | 端到端耗时 | < 20s |

### 3.2 生成物（自动产生，**不提交**，随时可重建）

| 路径 | 内容 | 大小 | 怎么重建 |
| --- | --- | --- | --- |
| `data/index/chunks.jsonl` | **2022 张卡片的清单**（纯文本，可以直接打开看！） | 1.7 MB | `uv run eq-ingest` |
| `data/index/pagecache/` | 页级解析缓存：改切块逻辑不用重解析 PDF | 3.7 MB | 自动 |
| `data/qdrant/` | **向量库**：每张卡片的 1024 维坐标 | 22 MB | `uv run eq-ingest` |
| `data/figure_cache/` | 从 PDF 里抠出来的 339 张 PNG | 51 MB | 自动 |
| `data/work_orders/` | Agent 建出来的工单（dry-run 模式下不产生） | — | `eq-ask` |
| `data/manuals/_probe/` | 手册体检时的临时下载目录（已忽略） | — | `check_manual.py` |

> **为什么生成物都不提交？**
> 因为它们是"派生物"：只要有 PDF + 代码，一条命令就能重新生成。
> 提交它们会让仓库变几十 MB，而且改一次代码就产生一大坨 diff。
>
> **唯一例外要看清**：`cases.jsonl` 和 `parts.json` **是提交的**。
> 因为它们虽然由脚本生成，但结果是**固定的**（有随机种子），且测试要用。

### 3.3 想亲眼看"卡片"长什么样

## 4. `scripts/` —— 一次性脚本（不是项目的常驻代码）

| 文件 | 干什么的 | 什么时候用 |
| --- | --- | --- |
| `gen_data.py` | 造 192 条假工单 + 24 条备件 | Day 1（已跑过） |
| `smoke_test.py` | **离线自检**：自造一个假 PDF，跑通"解析→切块→检索→渲染作业卡" | 每次改完代码 |
| `check_manual.py` | **手册体检**：数块 + 查乱码 + 判通过/不通过 | 下载新手册后 |
| `check_pagecache.py`（在根目录） | 临时自检：验证页级缓存「命中结果 == 现场解析」，且 PDF 变了就失效 | 改 `parse.py` 的缓存逻辑后用 |

> **`scripts/` 和 `src/` 的区别**：
> `src/` 里是"产品代码"（被别的代码 import）；
> `scripts/` 里是"我自己用的工具"（直接 `python xxx.py` 跑）。
>
> 注意 `check_manual.py` **是** git 跟踪的（Day 1 已提交）——它是数据采集环节的常驻工具，
> 换台机器要能重新体检手册，所以它不是一次性脚本。

## 9. 6 个命令分别在哪（记住这个就够跑）

| 命令 | 入口文件 | 干什么 |
| --- | --- | --- |
| `uv sync` | — | 装依赖 |
| `uv run python scripts/gen_data.py` | `scripts/gen_data.py` | 造假工单和备件 |
| `uv run eq-ingest [--no-vlm]` | `src/eqagent/ingest/pipeline.py` | PDF → 卡片 → 向量库 |
| `uv run eq-ask "问题"` | `src/eqagent/agent/run.py` | 跑一次 Agent，出作业卡 |
| `uv run eq-eval [--limit 10]` | `src/eqagent/eval/runner.py` | 跑评测，出数字 |
| `uv run streamlit run app/streamlit_app.py` | `app/streamlit_app.py` | 开界面 |

`eq-ingest` / `eq-ask` / `eq-eval` 这三个"短命令"是 `pyproject.toml` 里
`[project.scripts]` 那一节定义的，指向对应的 `main()` 函数。
这就是"装完之后能直接敲命令"的原理。

## 11. 一句话记一个文件（速查版）

index.py       书库管理：往向量库里存取
hybrid.py      两个管理员：向量 + 关键词 + 融合 + 重排
